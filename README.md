# Lugforth

> Unofficial fork of [uEforth](https://github.com/flagxor/ueforth) by Bradley D. Nelson,
> maintained by Luginfo10. It is not affiliated with the original author and is not
> endorsed by him. See [NOTICE](NOTICE) for what was added.

An EForth-inspired Forth bootstrapped from a minimalist C kernel.

Documentation site: [luginf.github.io/lugforth](https://luginf.github.io/lugforth/)

[WORDS.md](docs/WORDS.md): reference of the words, generated by `tools/words_reference.py`.

## Layout

```
common/      shared core (Forth sources and C headers)
ports/       one directory per platform: posix, web, windows, esp32, pico,
             pico-ice, gba, android, rpi (bare metal: QEMU, Raspberry Pi 3/4), efi (bare x86-64 PC)
examples/    example programs and benchmarks
tools/       build and conversion scripts
docs/        site/ (documentation website), SKILLS.md, WORDS.md, images/
lib/         shared Forth libraries (hashing)
attic/       old experiments
```

## Binaries

Pushing a tag such as `v7.0.8.1` (or running `.github/workflows/release.yml` by
hand) builds and publishes them.

* **Linux**: tarball and AppImage, built on Debian 10 (glibc 2.27 or newer). The
  AppImage carries the SDL2 libraries, the examples and a font. Run from a
  console it gives the terminal interface; a click on the desktop opens the window
  of `lugforth --gui` (a terminal if it cannot open).
  The examples are copied on first run to `~/.local/share/lugforth/examples`
  (`LUGFORTH_HOME` changes the directory) and never overwritten.
* **Android**: `lugforth-VERSION-android.apk` (arm64), built by hand with `ports/android/build_apk.sh`
  and attached to the release; signed with a debug key kept in `out/android/debug.keystore`, so keep
  that file to be able to update an installed copy.
* **Windows x64**: MSVC build, not started in CI yet. It has no SDL2: the SDL2 examples, `ed`,
  `writhdeck` and the console window are for the POSIX build (Linux) only.
* **macOS**: builds but does not start yet, so it is not published.

`lugforth --gui [file.fs]` (any Linux build with SDL2) opens a console window with a
smooth TrueType font, mouse selection and paste, and scrolling back. The menu stays
hidden until the button at the top right (or F10) is used: examples, text size,
colors (with a color picker), system fonts, help; Alt+Enter is full screen. Size, colors and font are kept in
`~/.local/share/lugforth/lugforth.ini` (`LUGFORTH_HOME` changes the directory), which
can be edited: `size=`, `margin=`, `fg=` and `bg=` (hexadecimal RRGGBB), `font=` (a TrueType file), `fullscreen=` (the key, `Alt+Enter` by default).

`lugforth-mini` (in the tarball, also alone) is the same POSIX build without the editors
(`ed`, `writhdeck`), SDL2, X11, the console window and the web and telnet servers: about 110 KB
against 260 KB, for machines that only need the interpreter. `ninja posix` builds both
(`out/posix/lugforth-mini`), and `--gui` says there is no window. From a source checkout the
mini can still load a part: `needs ports/posix/sdl2.fs`, then `sdl2` (SDL2 itself still has to
be installed).

Static binaries are not possible: Lugforth reaches libc, SDL2 and X11 through
`dlopen`/`dlsym`.

## Line editing

In a terminal, in the web terminal, in the SDL console of the Android app and
on the bare-metal Pi and PC (`common/lineedit.fs`): cursor keys, Home, End,
Delete, Ctrl-A/E/B/F/D/K/U/L, a history of 64 lines (up, down, not kept) and
Tab completion of words. After `include`, `needs`, `required`, `included`,
`s"`, `z"`, `r|` and `r~`, Tab completes file names instead (not on the web).
Piped input and the other ports use the plain `accept`.

## Pager

On a terminal (POSIX) and on the bare-metal consoles (`common/pager.fs`), the
output of a line typed at the prompt stops at each screenful with `-- more --`:
space shows the next page, Enter one more line, `q` or Esc stops. It is on by
default; `pager-off` and `pager-on` switch it (put `pager-off` in `autoexec.fs` to
keep it off). It does not act on a pipe, while a file is included, in a program
that reads keys, or in the SDL console. Lines wider than the screen are counted
as one, and a telnet session ending puts the plain `type` back.

## Text editor

`ed file.fs` (POSIX build, in a terminal or in the `--gui` window) opens or creates a
text file. Arrows, Home, End, PageUp, PageDown, Delete, Ctrl+arrows (word) and
Ctrl+Home/End; Tab inserts two spaces and Enter keeps the indentation. Selection with
Shift+arrows, or Ctrl+K to start and stop a selection; Ctrl+C, Ctrl+X, Ctrl+V; Ctrl+Z
undoes and Ctrl+Y redoes; Ctrl+F finds (Ctrl+N or F3 for the next one), Ctrl+G goes to a line; Ctrl+S saves
and Ctrl+Q quits (twice if the text changed). `.fs`, `.fth` and `.4th` files are
highlighted (comments, strings, words of the language, numbers, the name after `:`) in a
terminal that has colors; Ctrl+T cycles the color themes (`default`, `colorforth` with red
definitions and green words, `light`, `solarized`, `mono`), kept with the width and the goal of
`writhdeck` in `editor.ini` beside `lugforth.ini` (`theme=colorforth`, `width=`, `goal=`, `wrap=`). The code is `ports/posix/editor.fs`, compiled the first time `ed`
runs; `ports/posix/editor_tests.fs` tests its buffer.

`writhdeck file.t2t` is the same editor for writing, after [WrithDeck](https://github.com/luginf/writhdeck)
(`ports/posix/writhdeck.fs`, built on `editor.fs`, so both files are needed): lines wrapped
in a centered column, txt2tags and Markdown highlighting (headings, lists, `**bold**`,
`//italic//`, `__underline__`, `%` comments), and an Esc menu: `w` wrap, `f` focus (dims
the paragraphs but the current one, the line stays in the middle), `h` Hemingway (no
deleting or moving back), `t` timer (stopwatch or countdown), `o` outline of the headings,
`v` word occurrences (most used words first), `q` quit,
`s` statistics, `r` replace all, `g` daily goal, `Ctrl+Y` redo, `Ctrl+O` save and go back to the file browser (`writhdeck` alone starts there: Enter, `n` new, `/` filter, `r` rename, `d` delete, `b` backup), `a` autosave, `+`/`-` width, `c` color theme, `?` help. The
status bar shows the words, the words of the session and the progress to the goal.

## Examples

`examples/` has games, benchmarks and demos, see `examples/README.md`: SDL2 programs
(`sdl2_breakout.fs`, `fm/sdl2_fm.fs` (an FM synthesizer, MIDI keyboard in Linux and in the browser), `sdl2_roguelike.fs`, `sdl2_3d.fs` with turning wireframes, `sdl2_2048.fs`
with sliding tiles, `--no-anim` turns the animation off), the terminal `2048.fs`, and a small
rule based inference engine (`examples/inference/`, with a README in English and in French and a
Makefile that runs concrete scenarios). 2048, 3d and the inference engine are ports of projects of
Marc Petremann ([eForth Windows](https://github.com/MPETREMANN11/eForth-Windows)); they are GPL, unlike the rest of
the repository (see `NOTICE`). `make -C examples test-ports` runs their tests and `make -C examples smoke`
loads every SDL2 example.

## Varvara: running Uxn ROMs

`examples/varvara/` is a [Uxn/Varvara](https://100r.co/site/uxn.html) virtual machine written in
lugforth. `lugforth examples/varvara/varvara.fs program.rom` runs a ROM in an SDL2 window, like
`uxnemu` (Screen, Controller, Mouse, Datetime, Audio, File, Console input; F1 zoom, F3 screenshot,
F4 reboot, drop a ROM on the window; started without a ROM it shows a usage screen).
`uxncli.fs` runs a ROM in the terminal, like `uxncli`, and `launch.fs` is a launcher with options
(`-c` terminal, `-z` zoom, `-s WxH` screen size, `--no-mouse`, `-q`, tokens for writhdeck-uxn). The upstream opcode test (`opctest.rom`)
passes. It is about 60 times slower than the C uxn, so it suits ROMs that mostly wait for events;
see `examples/varvara/README.md`.

## Bare metal: QEMU and the Raspberry Pi

`ports/rpi/` runs lugforth with no operating system on 64-bit ARM: QEMU's
`virt` and `raspi3b` machines (which run fine on a Linux x86_64 PC), a
Raspberry Pi 3, and a Pi 4 (that one written blind). The console is the
serial line. The `sdl2` words are there too: screen, text, images, keyboard
and mouse, beeps and ABC tunes. Files are on the SD card (FAT12/16/32):
`include`, `ls`, and an `autoexec.fs` run at boot. `examples/sdl2_breakout.fs` and
`sdl2_roguelike.fs` run unchanged:

```
sudo apt install gcc-aarch64-linux-gnu picolibc-aarch64-linux-gnu qemu-system-arm
make -C ports/rpi run                   # the prompt, under QEMU virt
make -C ports/rpi roguelike BOARD=virt  # a QEMU window, with sound
make -C ports/rpi test                  # boots both machines and checks 121 things
```

What works where, what is tested and how, and what still needs a real board:
[ports/rpi/README.md](ports/rpi/README.md).

`ports/efi/` is the same on an x86-64 PC: a UEFI application,
`EFI/BOOT/BOOTX64.EFI` on a FAT32 USB stick, started by the firmware (Secure
Boot off, then the one-time boot menu, F12 on a Dell). It uses the
firmware's screen, keyboard and files: the console on the screen, the
`sdl2` words, `include` and the editors from the stick. It has no sound and
no mouse.

```
sudo apt install gnu-efi ovmf qemu-system-x86 dosfstools mtools
make -C ports/efi usb     # out/efi/usb.img, to dd onto a stick
make -C ports/efi run     # the same image under QEMU with OVMF
make -C ports/efi test    # 74 checks under QEMU
```

See [ports/efi/README.md](ports/efi/README.md).

## Building from Source

To build from source:

```
sudo apt install ninja-build gcc-arm-none-eabi
git clone git@github.com:luginf/lugforth.git
cd lugforth
./configure.py
ninja
```

The output goes to `out/`: `posix`, `web`, `windows`, `esp32`, `pico-ice`,
`pages` (the GitHub Pages site, `tools/make_pages.py`), plus `*-sim` builds used
for tests. A single platform: `ninja posix`, `ninja web`, `ninja win64`...

`./configure.py -f` skips the slower components (web, windows). `ninja install`
installs the posix build to `/usr/bin`. ESP32 boards are built and flashed with
`ninja esp32-flash` (also `esp32s2-flash`, `esp32s3-flash`, `esp32c3-flash`,
`esp32cam-flash`); set `PORT=com3` etc. to pick the port.
